# bench/grouping — 서브클래스 그룹화 실측

같은 클래스(Carton) 안에서 **서로 다른 품목을 구분**하는 기능의 설계를 실측으로 정한 기록.
2026-08-14 시작, 08-21 기준 실험 15건.

**팀 공유 문서**: `~/공유_서브클래스_그룹화_실험정리.{md,html}` (원리·결과·한계 전체)

## 결론 요약

| 모드 | 결과 |
|---|---|
| **정답 등록 후 배정** (운용 방식) | **98~99.6%** (8종 491객체) |
| 정답 없이 자동 군집 | 27군집으로 과분할, 섞임 0%(순도 100%) |

출발점(현행 7차원 유클리드)은 8종에서 **91.1%**.

### 최종 파이프라인

```
RFDETR 마스크 → 윗면 3D 사각형(estimate_top_face_v2, depth 필요)
  → 종횡비 보존 워프(긴 변 128px)
  ├─ ResNet50(분류층 제거), 종횡비 유지하며 긴 변 224px
  │    4방향 회전 임베딩 평균 → 2048차원 → PCA 16
  └─ 손수 측정: 색 3(Lab 중앙값) + 질감 2 + 물리 크기(긴 변)
  → 이어붙임(CNN 부분 ×0.35~0.5) → L2 거리 → 최근접 정답
```

## 측정 프로토콜 (결과보다 이게 자산)

1. 종류별로 **밝은 프레임**의 medoid 1개를 정답으로 등록
2. **어두운 프레임**의 객체를 최근접 정답에 배정 → 정확도
3. 종류를 4+4로 갈라 **학습에 쓰지 않은 4종**에서 채점

즉 "정답을 등록해둔 뒤 조명이 바뀐 상황"의 재현이다.

⚠️ **학습에 쓴 대상으로 평가하면 아무것도 증명하지 못한다.** 마할라노비스가 0.810 →
교차검증 0.752로 떨어진 것이 그 예다.

## 확인된 원칙

1. **회전 불변성이 결정적** — 방향 히스토그램에 FFT를 씌운 이유, CNN에 4방향 TTA가
   필요한 이유가 같다
2. **찌그러뜨리지 말 것** — 워프·CNN 입력 양쪽에서 종횡비 보존이 이겼다.
   반대로 **빈 공간(패딩)을 만드는 건 두 번 다 실패**했다
3. **물리 크기가 가장 강한 단일 신호** — F=45.5로 압도적. CNN은 리사이즈 때문에 크기를
   알 수 없으므로 손수 측정값을 반드시 붙여야 한다
4. **하드 컷은 위험** — 되돌릴 수 없어 측정 오차가 그대로 손실이 된다
5. **작은 표본의 순위는 믿을 수 없다** — 6종에서 MobileNet이 ResNet과 동급이었으나
   8종에서 −3.6%p로 갈렸다
6. **거리 함수는 L2로 충분** — 10종 비교에서 L2·코사인 공동 1위. 남은 여지는 축 가중

## 뒤집힌 결론 (재실험 방지용 기록)

| 한때의 결론 | 실제 |
|---|---|
| MobileNetV3가 ResNet과 동급, 13배 빠름 (6종) | 8종에서 91.1% vs 94.7% |
| 코사인이 유클리드보다 낫다 (AUC 실험) | 물리 크기가 들어오면 차이 없음 |
| 2단계 분리(크기→색)가 유리할 것 | 하드 86.1%, 소프트 91.8% — 이득 없음 |
| CNN 하위 11축은 무용 (F 지표) | 제거하면 오히려 손해 — 조합으로 기여 중 |
| 마스크 불량은 배제해야 | CNN이 인쇄로 복구 — 배제하면 손실 |
| 블록별 거리(색차·상대오차)가 타당 | 84.9% — 손으로 정한 결합 계수가 실패 |

## 한계

- **표본이 작다** — 8종 491객체, 시험 225개. 99.1%는 실패 2개이므로 세부 설정의 우열은
  가릴 수 없다. 6종 99.5% → 8종 98%대로 이미 떨어졌으므로 20종이면 또 떨어질 수 있다
- **depth가 없으면 쓸 수 없다** — 윗면 워프가 전제
- **Thor 실측 속도가 없다** — 종횡비 보존은 배치가 불가해 4090 기준 객체당 ~8ms.
  프레임당 40객체면 ARM에서 3~10초 예상 → "요청 시에만 그룹화" 구조에서만 가능.
  정사각 입력(97.8%, 5배 빠름) 절충이 현실적일 수 있다
- **코드 미반영** — 적용하면 특징 기저가 바뀌어 **기존 정답 뱅크가 무효**가 된다(재등록 필요)
