# bench/grouping — 그룹화(서브클래스) 측정

2026-08-14 실측. **정답 라벨 + 실제 조명 변화 + 물리 크기(mm)** 로 그룹화 성능을 잰다.

## 왜 이 벤치가 필요했나

그룹화 개선의 병목은 알고리즘이 아니라 **"무엇이 같은 박스인지"에 대한 정답이 없다**는
것이었다. 현장 프레임은 한 장에 여러 종류가 섞여 있어 사람이 몽타주를 눈으로 훑어야만
검증할 수 있었고, 그마저 부정확했다(같은 박스가 조명별로 갈린 것을 다른 박스로 오인).

해결: **한 프레임에 한 종류만** 담아 촬영(`deploy/capture_type.sh`) → 폴더명이 곧 라벨.

## 데이터

`~/box_types/<종류>[_single]/` — 종류당 쌓은 상태 6장 + 낱개 2장, 조명 on/off 두 버전,
depth(npz) 포함. 2026-08-14 기준 6종:

| 종류 | 실측 크기(mm) |
|---|---|
| blue_printed | 193 × 186 |
| navy_small | 193 × 182 |
| navy_long | 355 × 194 |
| pacific_long | 357 × 196 |
| pacific_short | 313 × 246 |
| swanson | 316 × 249 |

⚠️ **6종이 정확히 3개의 크기 그룹**을 이룬다(각 쌍의 크기 차이 2~4mm). 즉 크기만으로는
절반이 구분 불가하고 색·질감이 실제로 일해야 하는 구성이다 — 조명 강건성이 제대로
시험된다.

## 실행

```bash
export GROUPING_WORK=~/grouping_work          # 중간 산출물 폴더(기본값)
mkdir -p $GROUPING_WORK
cp <운영가중치>.pth $GROUPING_WORK/continual_master_operational.pth
python bench/grouping/box_detect.py      # 검출 + 마스크 + 물리 mm  → box_objs.pkl
python bench/grouping/box_eval.py        # 정답 라벨로 기준 측정
python bench/grouping/box_metric.py      # 실제 조명으로 거리 학습 + 교차검증
python bench/grouping/box_reg_source.py  # 등록 방식(낱개 vs 쌓임) 비교
```

## 측정 프로토콜 (결과보다 이게 중요하다)

- **조명 분할**: 종류별로 프레임을 밝기로 반 나눠 밝은 쪽 등록, 어두운 쪽 시험.
  실제 조명 on/off 로 찍었으므로 "등록해둔 뒤 조명이 바뀐 상황"과 같다.
- **거리 학습 교차검증**: 종류를 반으로 갈라 3종으로 배우고 **처음 보는 3종**에서 잰다.
  학습에 쓴 종류로 평가하면 무의미하다. 운영도 "거리는 한 번 배우고 새 박스는 등록만"
  이므로 이 시험이 실제 상황과 같다.
- **특징은 실운영 경로 그대로**: 물리 mm 크기 + 워프패치 질감(폴백 아님).

## 2026-08-14 결과

| 조건 | 정확도 | '기타' 이탈 |
|---|---:|---:|
| 고정 가중 + 낱개 등록 | 73.1% | 3.8% |
| 고정 가중 + 쌓인 상태 등록 | 88.2% | 3.6% |
| 학습된 거리 + 낱개 등록 | 76.6% | 0.0% |
| **학습된 거리 + 쌓인 상태 등록** | **94.3%** | **0.0%** |

- **낱개 등록은 15~18%p 나쁘다.** 옆 박스 가림·그림자가 없어 특징이 운영 조건과
  체계적으로 달라진다. 거리 학습으로도 메워지지 않는다(성격이 다른 문제).
- **실제 조명으로 배운 거리는 처음 보는 박스에서도 +5.2%p**(83.9% → 89.1%).
  반면 **HSV 합성 변형으로 배운 거리는 실제 조명에서 손해**였다(83.8% → 78.5%) —
  합성 조명은 화면을 균일하게 밝히지만 실제는 그림자·반사·색온도가 함께 바뀐다.
- 남은 실패는 **크기가 같은 쌍의 색·질감 혼동**(swanson ↔ pacific_short 68~77%).
  크기가 다른 쌍(navy_long/navy_small)은 100%다.

### 데이터가 매긴 축별 가중 (실제 조명 학습)

| 축 | 가중 | 비고 |
|---|---:|---|
| a | 2.13 | 색상축이 가장 강한 신호 |
| b | 1.74 | |
| size_long | 1.44 | 긴 변은 신뢰 |
| tex2(Canny) | 1.05 | |
| tex1(로그HP) | 0.90 | 합성 변형 학습 땐 0.19 로 버려졌었다 — **철회** |
| L | 0.88 | 밝기는 낮게 |
| size_short | 0.63 | 쌓이면 짧은 변이 이웃에 가려 부정확 |

현재 운영은 `W_COLOR=1.0` 으로 L·a·b 를 동일 취급하지만, 실측은 a·b 가 L 보다 2배
이상 중요하다고 말한다.

## 아직 코드에 안 들어간 것

학습된 거리는 **배선하지 않았다**. "누가 언제 재학습하나"(현장별 재학습 절차)를 먼저
설계해야 하고, 종류 수가 6개뿐이라 일반화 근거가 아직 얇다.
